# 🎨 GUI Generator Skill v2.1 — UNIFIED STANDARD

> Скилл структурирован в виде явных пронумерованных правил (RULE 1, RULE 2, ...) для однозначной интерпретации ИИ-моделью. Каждое правило самодостаточно.

---

## 🧩 ТЕРМИНОЛОГИЯ (единые обозначения)

**Важно: Header и Footer — это две РАЗНЫЕ зоны, не синонимы.**

| Обозначение | Значение |
|---|---|
| **Header** | Верхняя рамка меню. Всегда слоты 0-8 (1 ряд). У меню от 45 слотов Header дополнительно включает Row1 (9-17) — тогда Header состоит из 2 рядов. |
| **Row1** | Второй ряд Header'а (слоты 9-17). Появляется ТОЛЬКО у меню от 45 слотов. Не самостоятельная зона — часть Header'а. |
| **Footer** | Нижняя рамка меню. **Всегда ровно 1 ряд** (последние 9 слотов меню), независимо от размера меню. У Footer'а никогда не бывает второго ряда. |
| **Рабочая зона** | Всё, что находится МЕЖДУ Header'ом (включая Row1, если есть) и Footer'ом. |
| **Г** | Голова игрока/темы в слоте 0 |
| **С** | Стекло `GRAY_STAINED_GLASS_PANE`, display_name пустой |
| **Вк** | Кнопка управления меню (вкладка/раздел/переключатель) — живёт ТОЛЬКО в Header (слоты 2-7) |
| **К** | Обычная контентная кнопка (стат/предмет/элемент списка) — живёт ТОЛЬКО в рабочей зоне |
| **П** | Пусто (AIR) — только боковые стенки рабочей зоны |
| **Пг** | Пагинация (←/→) — только в меню от 54 слотов |
| **Д** | Доп. функциональная кнопка Footer'а (динамический элемент) |
| **B** | Back — кнопка возврата в Footer'е (динамический элемент) |
| **C** | Close — кнопка закрытия в Footer'е (статичный элемент, всегда на месте) |

**Два варианта структуры меню целиком:**
- **Header (1 ряд) + рабочая зона + Footer (1 ряд)** — для размеров 27, 36
- **Header (1 ряд) + Row1 (1 ряд, часть Header'а) + рабочая зона + Footer (1 ряд)** — для размеров 45, 54

## 📜 RULE 1 — Размеры меню

Стандартные размеры Love*-экосистемы: **9, 27, 36, 45, 54**.

- **18-слотовое меню НЕ используется** — исключено из стандарта полностью, не генерировать.
- **9-слотовое меню — СПЕЦИАЛЬНЫЙ случай.** Нет единого шаблона. Перед генерацией **всегда** спрашивать назначение и раскладку.
- **27 / 36** — Header (1 ряд) + рабочая зона + Footer (1 ряд). Без Row1.
- **45 / 54** — Header (1 ряд) + Row1 (1 ряд) + рабочая зона + Footer (1 ряд). Row1 обязателен.
- Любой другой размер (не из списка) — нестандартный, генерация запрещена без уточнения у Максима.

---

## 📜 RULE 2 — Золотое правило о стекле (ГЛАВНОЕ ПРАВИЛО)

**Стекло существует только в Header и Footer. В рабочей зоне стекла нет никогда.**

1. **Header** (слоты 0-8, плюс Row1 у размеров от 45) — рамка сверху меню.
2. **Footer** — рамка снизу меню, **всегда ровно 1 ряд** (последние 9 слотов), при любом размере меню.
3. **В Header и Footer не может быть пустого места.** Каждый слот этих зон — это либо стекло, либо функциональный элемент. Пустых (AIR) слотов в Header/Footer быть не должно никогда.
4. **Кнопка в приоритете над стеклом.** Если на каком-то слоте Header'а или Footer'а (кроме Row1 — там кнопок не бывает) должна быть кнопка — она полностью заменяет стекло на этом слоте.
5. **Динамическое возвращение стекла.** Если функциональный элемент Header'а или Footer'а динамический (в конкретный момент неактивен/недоступен — например, Back в standalone-меню, доп.кнопка без функции, голова в слоте 0 при отсутствии профиля) — на его месте **снова появляется стекло**, а не пустота. Слот никогда не остаётся пустым.
6. **Рабочая зона — только контент.** Между Header'ом и Footer'ом — либо контентные кнопки (К), либо пустота (П) на боковых стенках. Стекла в рабочей зоне нет никогда, ни при каких условиях.

---

## 📜 RULE 3 — Слот 0 (голова)

Слот 0 (часть Header'а) всегда требует уточнения перед генерацией:

- **Профиль напрямую** (`head-%player_name%`) — если меню про самого игрока (LoveAuth, LoveProfile, личная статистика)
- **Профиль косвенно** (`basehead-[Base64]`) — тематическая иконка (LoveClans — голова клана, LoveHunt — тема охоты, и т.д.)
- Если голова динамическая и в моменте отсутствует (RULE 2, п.5) — слот 0 становится стеклом.
- **Правило:** сомневаешься — спрашивай.

---

## 📜 RULE 4 — Кнопки управления меню (Вк) и их динамическое размещение

- **Вк живут ТОЛЬКО в Header'е, в фиксированном диапазоне слотов 2-7** (6 слотов максимум, первый ряд Header'а). Они никогда не появляются в Row1, в рабочей зоне или в Footer'е.
- **Расстояние между Вк — динамическое, зависит от их количества**, чтобы вкладки всегда выглядели визуально равномерно (центрированы внутри диапазона 2-7), а не жались к одному краю.
  - 1 Вк → слот **4** или **5** (по центру диапазона)
  - 2 Вк → слоты **3, 5**
  - 3 Вк → слоты **2, 4, 6** или **3, 4, 5** (равномерное распределение с максимальным зазором)
  - 4 Вк → слоты **2, 3, 5, 6** (симметрично, с центральным разрывом)
  - 5 Вк → слоты **2, 3, 4, 6, 7** (равномерно с минимальным отступом)
  - 6 Вк → слоты **2, 3, 4, 5, 6, 7** (весь диапазон занят)
- Слоты диапазона 2-7, не занятые Вк, заполняются стеклом (RULE 2 — в Header'е не может быть пустоты).
- Распределяй Вк с равным шагом между собой и равными отступами от краёв диапазона (слоты 1 и 8 — стекло-границы), а не просто заполняй подряд с левого края.

---

## 📜 RULE 5 — Row1 (второй ряд Header'а)

- **Row1 — это часть Header'а, а не отдельная зона и не часть Footer'а.**
- **Row1 появляется, начиная с размера меню 45 слотов и больше** (45, 54). В 9/27/36-слотовых меню Row1 нет — Header состоит из одного ряда.
- Когда Row1 есть — он **всегда полностью стекло**, без исключений. Это чистый разделитель между Header'ом и рабочей зоной.
- Row1 не бывает "опциональным" или зависящим от контента — если размер меню ≥45, Row1 обязателен и полностью стеклянный.
- **Footer при этом остаётся 1 рядом всегда** — у Footer'а никогда не появляется второй ряд, даже в 54-слотовом меню.

---

## 📜 RULE 6 — Рабочая зона

- Рабочая зона — это всё, что находится между Header'ом (включая Row1, если есть) и Footer'ом.
- Содержит **только** контентные кнопки (К) и пустые боковые стенки (П).
- **Боковые стенки рабочей зоны — всегда ПУСТО**, стекло там запрещено категорически, при любом размере меню.
- Функциональные элементы навигации (не основной контент) — это Вк, их место в Header'е (RULE 4), а не в рабочей зоне.
- **Пагинация (Пг)** используется **только в 54-слотовом меню**, слоты 36 и 44 (боковые стенки предпоследнего ряда рабочей зоны). В 27/36/45-слотовых меню пагинации не бывает.

---

## 📜 RULE 7 — Footer (всегда 1 ряд)

Footer — последние 9 слотов меню, **всегда ровно один ряд**, базовая раскладка одинакова для всех размеров:

```
[С][С][С][С][С][Д][B][C]   (по локальным позициям 1-8; всего 9 слотов в ряду, первая позиция тоже стекло)
```

По локальным позициям Footer'а (1-9):
- **Позиции 1-5:** Стекло (С)
- **Позиция 6:** Доп. кнопка (Д) — функциональная, опциональная. Если неактивна — стекло (RULE 2, п.5)
- **Позиция 7:** Back (B) — если меню Chained. Если Standalone или неактивен — стекло
- **Позиция 8:** Close (C) — **всегда**, статичный элемент, никогда не заменяется стеклом и не пропадает
- Реальные номера слотов зависят от размера меню — см. таблицу в RULE 8

## 🎭 ИСКЛЮЧЕНИЯ ИЗ ПРАВИЛ

### Исключение 1: HOPPER-МЕНЮ (Подтверждение/Отмена)

**Случай:** Меню подтверждения (Yes/No, Confirm/Cancel, Delete/Keep). Использует размер 9, но со своей фиксированной раскладкой (частный случай 9-слотового меню, RULE 8).

```
Слот:  0    1    2    3    4    5    6    7    8
      [С]  [✓]  [С]  [П]  [П]  [П]  [С]  [✗]  [С]

С = Стекло
✓ = Подтвердить — basehead-[Base64_yes]

## 🎨 ОФОРМЛЕНИЕ

### Цвета MiniMessage
```
&6 = gold      — основные кнопки, навигация
&a = green     — активные состояния, подтверждение
&c = red       — опасные действия, закрыть, отменить
&7 = gray      — описание, неактивный текст
&9 = blue      — офицеры, VIP, специальные роли
&f = white     — значения, информация, ключевые данные
&e = yellow    — внимание, уведомления, выделение
```

### Структура Lore (стандартная)
```
1. Пустая строка:            ''
2. Описание кнопки:          '&7Текст описания'
3. Значение (если есть):     '&7Значение: &fДанные'
4. Действие:                 '&aЛКМ &7— открыть'

## ✅ ЧЕК-ЛИСТ ПЕРЕД ДЕПЛОЕМ (ОБЯЗАТЕЛЬНЫЙ)

### Общее
- [ ] Размер меню — 9/27/36/45/54? (18-слотовое исключено)
- [ ] Если 9-слотовое — назначение и раскладка уточнены у Максима?
- [ ] Если размер нестандартный — согласован с Максимом (Исключение 4)?

### Header
- [ ] Слот 0 уточнён (профиль/тема/динамический)?
- [ ] Слоты 1 и 8 — стекло?
- [ ] Вк размещены только в 2-7, с динамическим равномерным центрированием по количеству (RULE 4)?
- [ ] Незанятые Вк слоты в 2-7 — стекло (не пусто)?
- [ ] Row1 есть только если размер ≥45, и он полностью стекло, без исключений?
- [ ] Row1 НЕ спутан с Footer'ом — это разные зоны?

### Рабочая зона
- [ ] Стекла в рабочей зоне нет нигде (RULE 2, п.6)?
- [ ] Боковые стенки рабочей зоны — пусто (не стекло, не контент)?
- [ ] Контентные кнопки — ТОЛЬКО `basehead-[Base64]` или `%player_head%`, никаких обычных материалов?
- [ ] Пагинация (если есть) — только в 54-слотовом, слоты 36/44?

### Footer
- [ ] Footer состоит РОВНО из 1 ряда (последние 9 слотов), даже в 54-слотовом меню?
- [ ] Позиции 1-5 (локальная нумерация Footer'а) — стекло?
- [ ] Доп.кнопка (Д): если активна — кнопка, если нет — стекло (не пусто)?
- [ ] Back (B): если Chained — кнопка, если Standalone/неактивен — стекло (не пусто)?
- [ ] Close (C) на месте всегда, без исключений?
- [ ] Ни одного пустого (AIR) слота в Header/Footer?
